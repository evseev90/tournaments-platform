# Трекер задач: локальный markdown

У репозитория нет remote, поэтому задачи и спеки живут как markdown-файлы в `.scratch/`.
Каталог коммитится вместе с кодом.

## Соглашения

- Одна фича — один каталог: `.scratch/<feature-slug>/`
- Спека — `.scratch/<feature-slug>/spec.md`
- Тикеты на реализацию — по одному файлу на тикет: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`,
  нумерация с `01`. Никогда не сводить тикеты в один общий файл.
- Состояние триажа — строка `Status:` в начале файла тикета (строки ролей см. в `triage-labels.md`)
- Комментарии и история обсуждения дописываются в конец файла под заголовком `## Comments`
- Заголовки и текст тикетов — на русском, имена файлов и slug — на английском

## Когда скилл говорит «опубликовать в трекер»

Создать новый файл в `.scratch/<feature-slug>/` (при необходимости создать каталог).

## Когда скилл говорит «получить нужный тикет»

Прочитать файл по указанному пути. Обычно пользователь передаёт путь или номер тикета напрямую.

## Операции навигации (wayfinding)

Используются `/wayfinder`. **Карта** — файл, у которого по одному **дочернему** файлу на тикет.

- **Карта**: `.scratch/<effort>/map.md` (разделы Notes / Decisions-so-far / Fog).
- **Дочерний тикет**: `.scratch/<effort>/issues/NN-<slug>.md`, нумерация с `01`, вопрос — в теле файла.
  Строка `Type:` задаёт тип тикета (`research`/`prototype`/`grilling`/`task`); строка `Status:` — `claimed`/`resolved`.
- **Блокировка**: строка `Blocked by: NN, NN` в начале файла. Тикет разблокирован, когда все перечисленные файлы в `resolved`.
- **Фронтир**: просмотреть `.scratch/<effort>/issues/` и найти открытые, разблокированные и незанятые тикеты;
  берётся первый по номеру.
- **Занять**: выставить `Status: claimed` и сохранить до начала любой работы.
- **Закрыть**: дописать ответ под заголовком `## Answer`, выставить `Status: resolved`,
  затем добавить указатель на контекст (суть + ссылка) в Decisions-so-far в `map.md`.
