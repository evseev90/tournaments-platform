# Доменная документация

Как скиллам читать доменную документацию репозитория перед изучением кода.

## Перед изучением кода прочитать

- **`CONTEXT-MAP.md`** в корне: карта ограниченных контекстов и связей между ними. Она ссылается
  на `src/<Context>/CONTEXT.md` — прочитать каждый, относящийся к теме задачи.
- **`docs/adr/`**: ADR, затрагивающие область, в которой предстоит работать. Общесистемные решения
  лежат здесь; контекстные, если появятся, — в `src/<Context>/docs/adr/`.
- **`docs/`**: механика форматов и алгоритмов (`formats.md`, `scheduling.md`, `statistics.md`).

Если какого-то из файлов нет — **продолжать молча**. Не отмечать отсутствие и не предлагать создать
заранее. Скилл `/domain-modeling` (через `/grill-with-docs` и `/improve-codebase-architecture`)
создаёт их лениво, когда термин или решение действительно устоялись.

## Структура файлов

Репозиторий мультиконтекстный (в корне есть `CONTEXT-MAP.md`):

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← общесистемные решения
└── src/
    ├── Tournament/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← решения контекста (по мере появления)
    ├── Scheduling/
    │   ├── CONTEXT.md
    │   └── docs/adr/
    └── Statistics/
        ├── CONTEXT.md
        └── docs/adr/
```

Новый контекст добавляется как `src/<Context>/CONTEXT.md` и строка в `CONTEXT-MAP.md`.
Меняешь язык — правишь глоссарий в том же коммите.

## Использовать словарь глоссария

Когда результат называет доменное понятие (в заголовке тикета, предложении рефакторинга, гипотезе,
имени теста) — брать термин так, как он определён в `CONTEXT.md` нужного контекста. Не уходить
в синонимы, которых глоссарий явно избегает. Помнить, что один и тот же человек в разных
контекстах зовётся по-разному (`Participant` / `ParticipantRef` / `Competitor`) — это намеренно.

Если нужного понятия в глоссарии нет — это сигнал: либо придумывается язык, которым проект
не пользуется (пересмотреть), либо есть реальный пробел (отметить для `/domain-modeling`).

## Помечать противоречия с ADR

Если результат противоречит существующему ADR — сказать об этом явно, а не переопределять молча:

> _Противоречит ADR-0003 (участники сопоставляются по имени), но стоит пересмотреть, потому что…_
