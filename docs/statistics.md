# Как работает статистика

Механика сквозных показателей.
Термины определены в [глоссарии контекста](../src/Statistics/CONTEXT.md).

## Откуда берутся участники справочника

Организатор вводит составы руками, списком. Отдельного выбора из справочника при создании турнира нет,
поэтому участники опознаются по нормализованному имени внутри аккаунта: «Пётр Волков», «петр волков»
и «  Пётр   Волков » — один и тот же человек. Решение и его цена описаны в
[ADR 0003](./adr/0003-competitors-matched-by-name.md).

Справочник пополняется по событиям `ParticipantAdded` и `ParticipantRemoved`: слушатель приводит состав
турнира в соответствие со справочником аккаунта. Турниры без владельца в статистику не попадают,
складывать их результаты некуда.

## Как считаются показатели

Статистика считается по сыгранным матчам на лету, отдельной проекции нет. Матч попадает в расчёт,
если у него есть результат и обе стороны опознаны как участники справочника.

Разбор счёта отдан доменным объектам контекста «Турнир»: правила «кто победил» и «сколько партий»
живут там, и дублировать их в SQL нельзя. Запрос достаёт матчи, а суммирует их код.

Участник без единого сыгранного матча всё равно виден в списке с нулями: справочник показывает,
кто вообще есть, а не только тех, кто успел сыграть.

## Что сознательно не сделано

Нет объединения и переименования участников справочника: опечатка в имени создаёт второго человека,
и исправить это сейчас можно только переименованием в самом турнире. Нет рейтинга вроде Эло,
нет статистики по сезонам и нет публичных профилей: справочник виден только владельцу аккаунта.
